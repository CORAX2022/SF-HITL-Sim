## 7. 方法与局限

- **检索**：GitHub `/search/repositories`，全部查询带 `stars:>100` 或 `stars:>50` 约束，按 `sort=stars` 取前 100；查询覆盖 7 大类关键词与 `topic:` 标签（abm、agent-based、crowd、sumo、traffic、mobility、digital-twin、llm-agents、human-in-the-loop、experiment、geospatial、spatial-analysis、transportation、urban-planning、flow-map 等）。原始响应全部缓存于 `raw/`。
- **核验**：关键词已知但未被检索命中的知名项目，逐个用 core API `/repos/{owner}/{repo}` 核验星标、许可证、默认分支、创建与推送时间；星标不足或近 3 年无推送者剔除（evoplex、abmgis、PedestrianCounter 即因此未入表）。
- **Gitee**：`https://gitee.com/api/v5/search/repositories` 实测对全部测试查询返回空数组（该接口现需 access token），故本次未能补充国内托管平台数据；GitLab / Codeberg / HuggingFace 未逐站检索。这意味着**中文社区的高星项目覆盖不完整**，若需要 Gitee 数据，需提供 token 后补检。
- **局限**：GitHub 仓库检索默认只匹配名称、简介与话题标签，不覆盖 README 全文，因此存在“确实相关但简介未提关键词”的漏检；类别归属由人工判定，一个项目只入一类（主要类别）。
- **合规**：全过程仅调用元数据 API 与网页，**未执行任何 git clone / 压缩包下载**。
