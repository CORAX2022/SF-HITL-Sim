# 系统架构设计

> 本文档描述"存量—流量空间建模驱动的参与式交互仿真：面向公共空间人员流动治理的人机协同实验平台"（下称"本平台"）的软件架构。
> 数学模型见 [`docs/model/存量-流量模型规范.md`](../model/存量-流量模型规范.md)。

---

## 1. 架构设计的第一原则：单一世界，同构接口

本平台最关键的设计决策是：

> **真实人类被试与 LLM 合成智能体，必须通过完全相同的接口与同一个仿真世界交互。**

这条原则直接决定了研究结论是否可信：

- 如果人类走一套 API、合成体走另一套，二者的行为差异就**无法归因于"人 vs AI"**，
  因为接口差异本身就成了混淆变量；
- 如果人类和合成体各跑一个世界实例，就**不能声称"共同驻留同一仿真环境"**，
  而这恰是本项目要挑战的研究缺口；
- 只有单一世界 + 同构接口，才能做**受控替换实验**：
  固定场景与人设分布，把混合比例从 100% 真人逐步替换为 100% 合成体，
  观察宏观流量演化的偏移量。这是回答"合成智能体能否替代真人做人群仿真"
  的唯一干净设计。

据此，系统被切分为三层，层间单向依赖。

## 3. 统一决策协议（架构的枢纽）

人类与合成智能体都必须产出同一种消息：

```jsonc
{
  "actor_id": "p03",              // 参与者匿名 ID 或合成体 ID
  "actor_type": "human",          // "human" | "llm" | "scripted"
  "round": 7,                     // 轮次
  "origin_unit": "plaza_north",   // 决策时所处单元
  "choice": "plaza_south",        // 目标单元 | "STAY" | "EXIT"
  "weight": 1.0,                  // 代表性权重
  "latency_ms": 4210,             // 决策耗时
  "confidence": 4,                // 自评把握 (1-5)，可选
  "reason": "南侧看起来人少",       // 开放文本，可选
  "issued_at": "2026-10-14T09:03:00+08:00"
}
```

设计要点：

1. **`actor_type` 只用于标注与分组分析，仿真内核不得据此改变计算逻辑。**
   内核看到的是"一个权重为 `w` 的决策者从 `origin_unit` 选择了 `choice`"。
2. **`weight` 使小样本外推成为可能**：20 名真人被试可通过权重代表
   200 人的群体，与合成体规模对齐。
3. **人类决策是异步到达的**：收集器设一个决策窗口 `window_ms`，
   超时未提交者按"STAY"处理并记录 `timeout: true`，
   这本身是有意义的被试行为数据（犹豫/放弃）。
4. **合成体的 `latency_ms` 是真实推理耗时**，可用于成本核算与
   "人机响应速度差异"分析；但它不参与仿真状态演化。

> 该协议是"同构接口"原则的落地形式。任何新决策者（真人、
> LLM、规则体、未来接入的强化学习体）只要实现该协议即可入网。

## 4. 轮次生命周期

一轮（round）的完整时序，对应数学模型 §5：

```
 t 开始
   │
   ├─[1] Broadcaster: 向全体在网决策者下发状态快照 state_snapshot(x(t))
   │
   ├─[2] Collector: 开启决策窗口 (window_ms)
   │        ├─ 人类：前端提交 → 写入 buffer
   │        ├─ LLM：本地推理（可并行）→ 写入 buffer
   │        └─ Scripted：立即产出 → 写入 buffer
   │
   ├─[3] Collector: 窗口关闭，汇总 buffer，标记超时者
   │
   ├─[4] Aggregator: 背景重力流 f^bg + 汇总 f^human + f^llm  →  f
   │
   ├─[5] Projector: 守恒投影 (Σ_j f_ij ≤ x_i) + 容量惩罚/硬阻挡
   │
   ├─[6] 状态推进: x(t+1) = x − 行和 + 列和 + b − d
   │
   ├─[7] Recorder: 落盘本轮全部数据（决策 + 状态 + 量表）
   │
   └─[8] 终止判定（轮次上限 / 参与者退出 / 主试终止）
 t+1 开始
```

**同步点**：只有在 [5]–[6] 之间存在全局同步。决策阶段 [2] 是异步并行的，
这样 LLM 推理延迟不会阻塞人类被试的节奏，反之亦然。

## 5. 技术选型与理由

| 组件 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 仿真内核 | **Python**（Mesa 风格或自研；见 `docs/verify/lane-b-*`） | 科学计算生态、易与数据采集/分析同栈 | Agents.jl（性能更好，但引入 Julia 双栈成本） |
| 人类实验前端 | **jsPsych**（浏览器端） | 精确计时、成熟的行为实验范式、易嵌入空间选择界面 | 自研 React（更灵活，但需自行处理计时与量表） |
| 多轮/多人协议 | **oTree** 式房间与轮次模型 | 天然支持"多人同步轮次 + 问卷 + 支付"，与本文闭环同构 | 自研 WebSocket 房间 |
| 前后端通信 | **WebSocket**（实时）+ REST（配置/导出） | 轮次同步需要服务端推送 | 轮询（延迟高，不推荐） |
| 数据落盘 | **JSONL + CSV**，事后转 SQLite/Parquet | 实验期抗崩溃、易审计；分析期高效 | 直接写 DB（实验期风险高） |
| LLM 接入 | 可插拔后端（云 API / 本地模型） | 成本与数据合规可切换 | 单一供应商（合规风险） |

> **重要**：本项目**不**依赖 SUMO / CityFlow / AB Street 这类精细仿真引擎
> 作为运行内核——它们正是本范式要"降低复杂度替代"的对象。
> 它们的作用是：(a) 提供场景数据格式与标定参考；
> (b) 作为多尺度接驳时的局部精化模块（见模型规范 §7）；
> (c) 作为对照组，量化聚合近似相对个体仿真的误差。

## 7. 关键工程风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 决策窗口与真实网络延迟 | 被试体验差，决策数据污染 | 服务端统一计时；`window_ms` 可配置；记录真实 `latency_ms` |
| 多人会话状态丢失 | 实验中断，数据作废 | 每轮结束后落盘；支持从快照恢复；前端断线重连 |
| LLM 推理延迟/成本波动 | 轮次节奏不稳 | 决策阶段异步；合成体结果可在窗口内到达即有效，否则按 STAY 并记录 |
| LLM 输出格式不合规 | 解析失败 | 强制结构化输出 + 重试 + 失败降级为 STAY 并标记 |
| 守恒约束被违反导致发散 | 仿真结果不可用 | `Projector` 强制比例投影（数学规范 §4.2）是**不可跳过**的一步 |
| 被试样本量小 | 外推性不足 | `weight` 机制；同时报告未加权与加权结果 |
| 数据合规（真人数据） | 伦理与法律风险 | 匿名化 ID、知情同意、仅存聚合量、伦理审查前置 |
| 上游项目许可证冲突 | 无法成果转化 | 逐仓库核对 SPDX（见各 `docs/verify/` 报告），避免 AGPL 污染 |

## 8. 最小可行路径（MVP → 完整平台）

**阶段 1｜内核可跑**（不涉及人类）
- 定义 1 个场景（10–20 个单元），实现空间图 + 重力流 + 守恒投影 + 状态推进；
- 用纯规则背景体跑通 200 轮，输出存量演化曲线；
- 验收：总人数守恒、无负存量、容量反馈生效——超软容量 `C_i` 时触发进入方向拥挤惩罚与硬阻挡（允许存量暂时越过 `C_i`，口径见模型规范 §4.1）。

**阶段 2｜接入合成智能体**
- 实现 `LLMAgent`，按统一决策协议产出选择；
- 验收：合成体加入后流量分布发生可解释变化；LLM 失败可降级不中断。

**阶段 3｜接入真人被试**
- 实现 jsPsych/oTree 式前端 + WebSocket 轮次同步；
- 验收：被试能看到状态、提交选择、收到反馈；决策与量表数据完整落盘。

**阶段 4｜混合实验**
- 混合比例控制；受控替换实验；数据分析模块（拥挤弹性、人机一致性）。

**阶段 5｜情景推演**
- 多方案对比（空间营建方案 A/B），输出决策支撑报告。
