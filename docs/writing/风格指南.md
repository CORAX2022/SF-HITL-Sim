# 中文科技写作风格指南

> 适用对象：本论文仓库 `paper/` 下的全部中文正文、摘要、图注、表注与评审回复。
> 目标读者是**规划、仿真、人机交互三个领域的审稿人**，因此写作的第一要求是
> **可核查**，第二是**可读懂**，第三才是**好看**。
>
> 本指南只规定"怎么写"，不规定"写什么"；每一条规则都给出可执行判断。

---

## 1. 总原则

按优先级排序：

1. **准确**：每个论断有出处，每个数字可回溯（见 `paper/README.md` §8）。
2. **简洁**：删掉不影响理解的形容词、连接词、背景铺陈。
3. **连贯**：一段一个意思，段首句给出该段结论。
4. **克制**：不承诺证据没有达到的结论，不预测未完成的实验。

**一句话检验法**：读每一句，问"如果删掉它，读者会失去什么可核查的信息？"
答不上来，就删。

## 2. 术语一致

### 2.1 强制规则

- 同一概念**全文只用一种写法**；首次出现给中英对照，之后只用中文。
- 术语以 [`术语表.md`](术语表.md) 为唯一准绳；新增术语先入表，再使用。
- 不要在正文里混用同义变体。以下每组**只允许左边**：

| 只允许 | 禁止 |
| --- | --- |
| 存量—流量（模型/建模） | 存量-流量、存量流量、stock flow |
| 人在回路（HITL） | 人机回路、人在环、human in the loop（正文中） |
| 合成智能体 | 合成体（正文首次定义后可简称，须明示）、虚拟智能体、AI 角色 |
| 参与式仿真 | 参与仿真、参与型仿真 |
| 人机协同 | 人机协作（除引用原题名）、"人与 AI 协同"式口语表述 |
| 统一决策协议 | 决策接口（口语）、统一接口 |
| 轮次 / 决策窗口 | 回合、轮、时间片（按语境严格区分） |
| 守恒投影 | 守恒修正、归一化 |
| 空间单元 | 空间格子、分区（指代具体划分时可用"分区"，但不得与"空间单元"混用为同一概念） |

> 例外：**引用文献原题名时保持原文**，不得为了统一而改写他人题目。

### 2.2 缩写规则

- 首次出现：中文全称（英文全称，缩写），之后用缩写；
  例：人在回路（human-in-the-loop, HITL）。
- 摘要中缩写最多 3 个；正文中超过 5 个缩写时，加一张缩写表。
- 全文缩写大小写统一：`LLM`、`HITL`、`ABM`、`BNE`。

## 3. 全半角与标点

### 3.1 基本规则

| 场景 | 规则 | 例 |
| --- | --- | --- |
| 中文句子 | 用全角标点 | 本文提出两种设计约束：其一……；其二……。 |
| 中英混排 | 英文词与中文之间留半角空格 | 使用 LLM 合成智能体做对照 |
| 数字与单位 | 数字与中文单位之间留半角空格 | 200 轮、25 人、12 个单元 |
| 数字与百分号/符号 | 不留空格 | 82.8%、`p < 0.05`、1e-13 |
| 括号 | 中文语境用全角 `（）`；纯英文/公式用半角 `()` | 三种条件（A/B/C）与 `f(x)` |
| 引号 | 中文用 `“”`，不混用 `""` | 所谓“闭环”指…… |
| 破折号 | 用 `——`（占两个字符） | 核心观察——人的选择即流量——决定了…… |
| 连接号 | 概念并列用 `—`（一字线） | 存量—流量、人—机 |
| 省略号 | 用 `……`，不用 `...` | 见 §6…… |
| 书名号 | 中文文献与标准用 `《》` | 《城市规划学刊》 |

### 3.2 常见错误

| 错误 | 正确 |
| --- | --- |
| 存量-流量 | 存量—流量（连接号用一字线） |
| 20人 | 20 人 |
| 82.8％ | 82.8% |
| LLM智能体 | LLM 智能体 |
| (见第6章) | （见第 6 章） |
| 图6-1 | 图 6-1 |
| 他说"……" | 他说“……”，或直接引述不加引号 |

### 3.3 标点的"三不"

1. **不用问句和感叹号**（除引述被试原话）；
2. **不用分号堆叠三个以上并列句**（拆段）；
3. **句末不加空格**，段落之间只空一行。

## 4. 数字与单位

### 4.1 何时用阿拉伯数字

- 全部**计量、统计、百分比、时间、编号**用阿拉伯数字：`200 轮`、`12 个单元`、
  `37.8 秒`、`24 项测试`、`82.8%`。
- **序数**可用汉字或阿拉伯数字，但全文统一：本文统一用`第 6 章`、`第 2 节`。
- 句首不用阿拉伯数字，改写句子：`200 轮仿真中……` → `在 200 轮仿真中……`。

### 4.2 精度与量级

- 同一张表、同一段落内精度**必须统一**：`192.0 / 129.2 / 58.0`，不可出现 `58`。
- 小数位数以**证据精度**为准：模拟输出报 1–3 位，不要报 `82.76234%`。
- 科学计数法：`9.734e-13` 或 `9.734 × 10⁻¹³`，全文统一；
  叙述时写"1e-13 量级"，不要写"约等于 0"。
- 大数用千分位半角逗号：`18,023 行`；全篇统一，不得有的地方用逗号、有的用空格。

### 4.3 单位

- 中文单位直接写在数字后（留半角空格）：`25 人`、`12 个单元`、`200 轮`；
- 国际单位用符号：`5 m`、`1.2 m/s`，数字与符号间留空格；
- 复合单位不加中文"每"混写：`人/分钟` 或 `人·分钟⁻¹`，全篇统一；
- 变化率必须带符号：`+82.8%`、`−51.6%`（负号用 U+2212 `−`，不用连字符 `-`）。

## 5. 图表题注

### 5.1 图

- **图题在图下方**，格式：`图 <章>-<序号> <中文题名>`
- 图注中如有来源/许可，另起一句或加括号：

```
图 6-1 三模式剩余人数演化曲线对比（作者原始结果 vs 本文复现）
数据源：`_nlogo_run/repro_experiment1.csv`；复现模型为第三方 CC BY-SA 4.0 成果。
```

规则：

- 图题**不加句号**；图注中的说明句加句号；
- 图题说明"是什么"，不说明"说明什么"（后者写在正文）；
- 正文引用写"如图 6-1 所示"，不写"见下图""上图"；
- 图中所有符号、缩写、颜色含义必须在图例或图注中给出。

### 5.2 表

- **表题在表上方**，格式：`表 <章>-<序号> <中文题名>`
- **表注在表下方**，以"注："开头，写口径、单位与数据源：

```
表 6-1 三种条件的守恒性检验（200 轮）

| 条件 | 轮数 | 最大总量漂移 | 判定 |
| --- | ---: | ---: | --- |
| A 纯背景流 | 200 | 9.734e-13 | PASS |

注：漂移为"总量变化 − 边界净流入"绝对值的最大值；数据源 `data/demo/loop_demo_summary.json`。
```

规则：

- 表题不加句号；
- 数字列右对齐，文本列左对齐；
- 空值写 `—`，不留空（留空会被读成 0）；
- 表内不出现"同上""见上文"。

### 5.3 编号

- 编号 = 章号 + 章内序号，按出现顺序顺延，**不得跳号、重号**；
- 增删图表后必须全文检查引用（`grep` 图号是最快的方法）；
- 计划但尚未制作的图不得在正文引用（见 `paper/figures/README.md` §4）。

## 6. 时态与语态

### 6.1 中文

- **主语用"本文/本研究/本文模型"**，不用"我们"（多人合著的中文期刊可酌情用"我们"，
  但全篇统一）；
- 描述已完成的工作用陈述句，不加"已经""成功地"等冗余副词：
  `本文实现了……` 已含完成义，不必写 `本文成功地实现了……`；
- 描述未完成的工作必须显式标注：`尚未开展`、`待后续工作检验`，
  **不得用将来时态伪装成结果**（如"本研究将证明……"出现在结果章）。

### 6.2 英文（摘要与英文稿）

- 描述方法、模型、结论用**一般现在时**：`This paper proposes…`, `The kernel enforces…`；
- 描述已完成的实验动作可用现在完成时或过去时，但全文统一：
  `We reproduced…` 或 `Reproduction shows…`；
- 不用 `will` 描述本文工作；
- 语态：方法用被动或主动均可，但**同一节内统一**；避免 `It can be seen that…`
  这类空转被动。

## 7. 篇幅控制

| 位置 | 上限建议 | 说明 |
| --- | --- | --- |
| 单句 | 60 字 | 超过就拆句；中文长句是"AI 腔"的常见来源 |
| 单段 | 4–8 句 / 200 字 | 一段一事；超过就分段 |
| 摘要 | 300–500 字（中文）/ 250 词（英文） | 不含关键词 |
| 引言 | 1500 字 | 背景 ≤2 段，综述 ≤3 段，贡献用列表 |
| 单节 | 800–1200 字 | 超过说明该节混了两个主题 |

删减优先级（从先删到后删）：感叹与评价性形容词 → 铺垫性背景 → 与主线无关的
文献 → 同义重复的解释。

## 8. 避免 AI 腔、空话与排比堆砌

### 8.1 识别特征

- **三段式排比**："不仅是……而且是……更是……"；
- **万能开头**："随着……的不断发展""在当今时代""近年来，……日益受到关注"；
- **空转动词**："赋能""助力""抓手""闭环生态""深度融合""全方位"；
- **无主语判断**："具有重要意义""提供了新的思路""奠定了坚实基础"；
- **模糊程度词**："显著""大幅""极大""一定程度上"——除非给数值；
- **伪逻辑连接**："值得注意的是""不难发现""众所周知""综上所述"；
- **过度解释**：把读者当外行，反复定义同一概念。

### 8.2 反例 → 正例对照（12 组）

| # | 反例 | 正例 | 问题 |
| --- | --- | --- | --- |
| 1 | 随着城市化进程的不断加快和人们生活水平的日益提高，公共空间人员流动治理问题日益受到学界和业界的广泛关注。 | 公共空间人员流动治理需要两类工具：实施前的情景推演，实施后的行为解释。 | 万能开头，零信息 |
| 2 | 本文旨在深入探讨存量—流量空间建模在参与式交互仿真中的应用路径与实现机制。 | 本文回答两个问题：人的空间选择如何进入聚合模型；真人与合成智能体如何在同一世界中受控对比。 | "深入探讨""路径与机制"为空转 |
| 3 | 本文的研究具有重要的理论意义和现实意义。 | 其价值在于：聚合模型使情景推演的成本可控，统一协议使人机对照可归因。 | 无主语判断，不可核查 |
| 4 | 实验结果表明，该方法取得了非常显著且巨大的提升。 | 注入 20 名模拟被试的选择后，喷泉观景区存量上升 82.8%（124.879→228.232）。 | 模糊程度词，无数据 |
| 5 | 值得注意的是，值得注意的是，模型在三种条件下均表现良好。 | 三种条件的守恒检验全部通过，最大总量漂移处于 1e-13 量级（表 6-1）。 | 口头禅重复，指代含糊 |
| 6 | 平台不仅提供了仿真能力，而且提供了数据采集能力，更提供了人机协同的能力，为后续研究奠定了坚实基础。 | 平台同时承担两件事：推演情景（输出流量再分配），采集证据（输出选择、反应时与量表）。 | 三段排比 + 空转结尾 |
| 7 | 我们做了一个实验来验证我们的想法。 | 本文在 12 单元演示场景上运行 3 种条件 × 200 轮，检验守恒性与注入效应。 | 口语化，缺规模信息 |
| 8 | 该结果充分证明了合成智能体可以替代真人进行人群仿真。 | 该结果只说明闭环机制有效；合成智能体能否替代真人（H3）尚未检验。 | 结论超出证据 |
| 9 | 本文首次提出了一种全新的空间仿真范式，填补了国内外研究空白。 | 在本文核查的语料范围内，尚未见到把聚合空间模型、真人回路与合成智能体同场整合的实验平台。 | 首创宣称 + 未核查的"填补空白" |
| 10 | 未来将进一步深入研究，不断完善平台功能，拓展应用场景。 | 后续按依赖顺序完成：LLM 合成体接入 → 真人实验（H1/H2/H5）→ 混合比例扫描（H3）→ 同双模型对照（H4）。 | 空头展望，不可执行 |
| 11 | 图1：存量演化 | 图 6-1 三条件存量演化（A 无人 / B 注入 / C 混合） | 题注缺编号规范与要素 |
| 12 | 本文提出的方法对于城市规划和公共安全管理领域都具有广阔的应用前景。 | 该方法适用于场地级人流情景比较；涉及踩踏力学的安全评估须回到个体模型（§7.4）。 | 泛化断言 + 未界定边界 |

### 8.3 自检方法

1. **删词测试**：删掉句中的形容词与连接词，句子是否仍成立？成立就删。
2. **指代测试**：每个"该""其""这"能否明确指向上一句的具体名词？不能就改写。
3. **数值测试**：每个"显著""大幅"能否替换为具体数字？不能就删掉。
4. **朗读测试**：读出来是否像人话？连续三个"的"就该改。
5. **对照测试**：本段与上一段是否在说同一件事？是就合并。

## 9. 段落与衔接

- **段首句给结论**，不要"总-分-总"绕三圈；
- 段落之间用**内容衔接**（上段末尾的问题 → 下段开头的回答），少用"首先/其次/最后"；
- 一个列表项不超过两行；列表前必须有一句引导句；
- 章节开头用 1–2 句交代"本节做什么、不做什么"。

## 10. 引用与断言强度

### 10.1 断言强度必须与证据匹配

| 证据强度 | 允许的写法 | 禁止的写法 |
| --- | --- | --- |
| 单篇文献 | 某文报告了…… | 已有研究普遍认为…… |
| 多篇文献 | 在本文核查的语料中，A、B 与 C 均…… | 学界一致认为…… |
| 本文可复现实验 | 本文测得……（给出数值与文件） | 实验证明该机制普遍成立 |
| 本文设计论证 | 本文论证了……在逻辑上可行 | 本文验证了……有效 |
| 尚未开展 | 待后续工作检验 | 预期将取得良好效果 |

### 10.2 引用格式

- 正文引用用 `[@key]`，多篇 `[@key1; @key2]`；
- 引用位置放在**判断之后**，不要放在段尾笼统挂一串；
- 引用他人观点时写明"某文认为"，不把文献结论写成自己的发现；
- 转引一律避免（本仓库所有文献均有本地 PDF 或核验记录，应直接引用原文）。

### 10.3 不确定性的写法

- 参数未标定：`演示场景的容量与吸引力为示意值，正式实验须依实测标定`；
- 复现边界：`door-width 无法从作者输出反推，本文取 6`；
- 结论范围：`该结论限于本文核查的 28 篇语料`。

## 11. 成稿前自查表

- [ ] 全文术语与 [`术语表.md`](术语表.md) 一致；
- [ ] 中英混排有空格，标点全半角正确，负号统一为 `−`；
- [ ] 数字精度全篇统一，百分比带符号，大数统一千分位；
- [ ] 每个图/表都有编号、题注与来源；
- [ ] 没有"随着……的发展""具有重要意义""显著提升"式句子；
- [ ] 没有超出证据的结论（对照 `paper/sections/06-结果与验证.md` §6.8）；
- [ ] 没有把未完成工作写成结果；
- [ ] 每个 `[@key]` 可解析，无未核实文献被当作定稿依据；
- [ ] 旧题名、旧平台名已全文检索并清除；
- [ ] 文件 UTF-8 无 BOM、LF 换行、末尾一个空行。
