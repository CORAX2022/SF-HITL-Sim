# 可用项目选型与建设计划

> **输入**：`docs/repos-survey/repos.json`（192 条经 API 核验的项目，全部 star>100 且近 3 年活跃）
> **约束**：本文所有推荐均指向 `repos.json` 中的真实条目；许可证结论与 `repos.json` 一致。
> **标记约定**：`✅实测` = 本机实际执行并观测到输出（证据见 `docs/verify/`）；`📋元数据` = 仅由 API 元数据与官方文档推断，**本机未验证**。

## 0. 一句话结论

**内核自研 + 实验层用 jsPsych/oTree + LLM 层薄适配 + SUMO 仅作外部标定**——四件事里三件今天就能跑，唯一需要在"少量改造"和"重投入"之间做选择的是**合成智能体接入方式**。本机无编译器/无 Julia/无 cargo 的事实，已经把选型空间压缩得很干净：任何需要编译或引入第二语言运行时的仿真引擎，在本机都只能当参考，不能当运行内核。

### 三条战略判断（来自 `docs/repos-survey/统计.md`），直接决定选型

1. **人群/行人仿真是全部 7 类中最薄弱的一类**（GitHub 上同时满足 star>100 且近 3 年活跃的仅 10 个，且全是微观内核）。→ 这解释了为什么**本项目的空间聚合层必须自研**，也说明自研层就是论文创新点所在，不应外包给现成项目。
2. **LLM 社会仿真是增长极，但普遍用抽象图而非真实路网**（OASIS 5270★、AgentSociety 1340★、Concordia 1780★）。→ 合成智能体层应当**薄适配、可替换**，不绑定单一平台；真实路网耦合留给本项目自研层。
3. **系统动力学工具链极其单薄**（全类仅 7 个，bptk_py 36★、simlin 99★ 未过阈值）。→ "存量-流量 + 多智能体"混合建模**没有现成答案**，PySD 只解决"存量-流量侧"，多智能体侧必须自研。

## 1. 分级方法与本机约束

### 1.1 本机已实测的硬约束（决定分档）

| 约束 | 实测状态 | 直接后果 |
|---|---|---|
| C/C++ 编译器（MSVC/gcc/clang） | ❌ 无 | CityFlow、mapnik、OSRM、Valhalla、s2geometry 无法构建 |
| cmake / ninja | ❌ 无 | 同上 |
| Rust (cargo) | ❌ 无 | AB Street 无法构建 |
| Julia | ❌ 无 | Agents.jl 无法运行（仅静态分析） |
| conda | ❌ 无 | 依赖 conda 的生态不可用 |
| Go | ❌ 无 | Fault 只能取预编译二进制 |
| Python | ✅ `py -3.13`（3.13.3）+ `uv` | Mesa 要求 ≥3.12，满足 |
| Node | ✅ v24.15.0 + pnpm + npm | jsPsych / kepler.gl / deck.gl 可用 |
| SUMO | ✅ **1.27.0 预编译已装**（`F:\SUMO`，含 JuPedSim） | 无需装 150 MB wheel，`sumolib`+`traci` 即可驱动 |
| GitHub 直连 | ❌ DNS 劫持至 127.0.0.1 | 取源码须走 `scripts/gh-fetch.ps1`（gh-proxy 代理） |
| PyPI / npm | ✅（建议 aliyun / npmmirror 镜像） | 纯 Python/JS 依赖无障碍 |

> 分档依据 = **语言运行时是否已具备（或 pip/npm 可装）+ 许可证是否允许嵌入交付物 + 是否需要编译器/数据库/大资源**。

### 1.2 三档定义

| 档位 | 定义 | 判定标准 |
|---|---|---|
| **S 档｜开箱即用** | pip/npm 可装，或本机已具备运行时；**今天就能驱动本项目** | 纯 Python/JS/WASM，无编译步骤 |
| **A 档｜需少量改造** | 需写适配层 / 配置 / 协议转换，但无编译与重型依赖 | 可 pip/npm 装，需 1 个薄封装 |
| **B 档｜需较重投入** | 需编译器 / 数据库 / 第二种语言运行时 / 大规模资源；**仅作参考或对照** | 本机不可构建或运维成本高 |

### 3.2 仿真编排层（② 轮次调度 + 聚合 + 守恒投影）

**采用：**

| 位置 | 选择 | 理由 |
|---|---|---|
| **运行内核** | **本项目自研 `src/core/`** | ✅实测 24/24 单测通过，守恒漂移 ~1e-12（`9.73e-13 / 1.23e-12 / 8.74e-13`）；✅闭环演示 200 轮×3 条件全 PASS |
| 调度/情景/采集管道 | [mesa/mesa](https://github.com/mesa/mesa)（Apache-2.0） | ✅实测 4.0.0a0 跑通 `CellAgent`/`OrthogonalMooreGrid`/`DataCollector`/`agentset.do()`；`Scenario`+`spawn_replications` 契合多方案推演 |
| 场景与路网来源 | [eclipse-sumo/sumo](https://github.com/eclipse-sumo/sumo)（**EPL-2.0**，**仅外部调用**） | ✅实测：`sumolib` 读到 `from=A to=B len=100.0m lanes=2 speed=13.89`，恰好覆盖"单元/邻接/成本/容量"四项输入；TAZ 与空间单元语义直接对应 |
| 空间数据准备 | [gboeing/osmnx](https://github.com/gboeing/osmnx) + [c2g-dev/city2graph](https://github.com/c2g-dev/city2graph) + [geopandas/geopandas](https://github.com/geopandas/geopandas) | 📋 三者组合覆盖"OSM 路网 → 空间单元 → 图结构"全链路，许可证全为宽松型 |

**关键判断（✅实测依据）：** [mesa/mesa](https://github.com/mesa/mesa) 的 `Cell` 公开属性中**不存在** `stock`/`flow` 字段，只有 `agents`/`capacity`；单元人数必须由 `len(cell.agents)` 反推——即"先有代理才有聚合量"，与本研究"不追踪个体、只保留聚合存量"的立场相反。**因此 Mesa 只能当调度骨架与个体级对照，不能当存量-流量内核。** 另需注意 Mesa 4.0.0a0 的破坏性 API 变更：`mesa.space`→`mesa.discrete_space`、`mesa.datacollector`→`mesa.datacollection`、`Model(seed=)`→`Model(rng=)`；不规则分区用 `VoronoiGrid(centroids_coordinates=...)`（✅实测签名），正好对上本项目"不等面积单元"。

**被拒绝的替代方案与取舍：**

| 替代 | 拒绝理由 |

| [a-b-street/abstreet](https://github.com/a-b-street/abstreet)（Apache-2.0，8,187★） | ✅实测**缺 cargo**；且其个体级高保真路线正是本范式要替代的对象 → 概念参考 |
| [JuliaDynamics/Agents.jl](https://github.com/JuliaDynamics/Agents.jl)（MIT，920★） | **无 Julia 运行时**（⚠️运行验证未执行，仅静态分析）→ 待 >10⁵ 代理时再评估 |

## 4. 建设计划（7 阶段，共 35 人天 + 伦理日历时间）

> 人天 = 1 名熟悉 Python/前端的开发者净工时；不含伦理审查的等待时间。
> 每阶段均给出**可检验的验收标准**（可脚本化判定）。

### 阶段 0｜环境搭建与依赖固化（2 人天）

- **交付物**：`docs/tooling/快速启动清单.md` 全部命令逐条跑通；`.venv-core`/`.venv-otree`/`.venv-sumo` 三个虚拟环境 + `package.json` 锁文件；`requirements.lock`。
- **验收标准**（全部可脚本判定）：
  1. `py -3.13 tests\test_core.py` → `24/24` 通过；
  2. `F:\SUMO\bin\sumo.exe --version` → 输出含 `1.27.0` 与 `JuPedSim`；
  3. `.venv-otree\Scripts\otree.exe test --export` → 退出码 0 且生成导出文件；
  4. `cd deploy\repos\jsPsych; npm run build` → `59/59 successful`；
  5. 三个 venv 的 `pip freeze` 落盘并 SHA256 记录。
- **风险与回退**：PyPI 镜像缺包（✅实测 aliyun 装 `requests` 失败）→ 回退 `-i https://pypi.org/simple/`；GitHub 直连失败 → 一律走 `scripts/gh-fetch.ps1`。

### 阶段 1｜场景数据准备（4 人天）

- **交付物**：`configs/scenarios/*.json`（≥3 个场景：演示广场、真实片区、对照网格）；`scripts/sumo_to_units.py` 增强版（支持 TAZ 分区、容量换算）；`data/scenarios/` 下的 SUMO 原始 net/rou 与转换结果；场景校验器 `scripts/validate_scenario.py`。
- **验收标准**：
  1. 每个场景通过 `validate_scenario.py`：邻接对称性、容量>0、无孤立单元、入口/出口至少各 1；
  2. 由 SUMO 路网转换出的单元数、边数与 `sumolib` 直读结果**逐项一致**（脚本 diff）；
  3. 真实片区场景的单元数 ≥ 30 且 OD 需求非零；
  4. 场景 JSON 的 schema 校验通过（`docs/model/存量-流量模型规范.md` 字段表）。
- **风险与回退**：OSM 数据获取失败（网络）→ 回退用 SUMO 自带示例路网或手绘小型场景；TAZ 数据缺失 → 用 `edge` 直接当单元。

### 阶段 2｜内核接入与统一协议固化（5 人天）

- **交付物**：`src/orchestrator/`（Scheduler / Collector / Aggregator / Projector / Recorder / Broadcaster）；`schemas/decision.schema.json`（统一决策协议 JSON Schema）；决策协议的人类/LLM 两条路径的校验单测；`examples/run_loop.py` 升级为调用 orchestrator。
- **验收标准**：
  1. `src/core` 单测仍 `24/24`；
  2. 决策消息经 JSON Schema 校验：合法消息 100% 通过、5 类非法消息 100% 拒绝（单测覆盖）；
  3. 一轮闭环：状态快照 → 决策窗口 → 聚合 → 守恒投影 → 落盘，端到端可复现，且**守恒漂移 < 1e-9**；
  4. Recorder 落盘的 JSONL 可完整重建状态序列（回放脚本断言逐轮相等）。
- **风险与回退**：决策窗口与网络延迟耦合 → 服务端统一计时并把 `latency_ms` 记为数据而非控制量；守恒被违反发散 → `Projector` 为**不可跳过**步骤（比例投影）。

### 阶段 3｜真人被试链路（8 人天，含伦理前置）

- **交付物**：jsPsych 被试端（空间状态可视化 + 单元选择 + 量表 + 计时）；WebSocket 服务（`src/server/`）；oTree 式房间/轮次骨架（或自研等价的房间管理）；断线重连与快照恢复；预实验脚本与 SOP；伦理审查材料包（知情同意书、数据匿名化说明、审查申请表）。
- **验收标准**：
  1. **技术**：3 个并发浏览器会话跑通 ≥10 轮，每轮决策与量表 100% 落盘，`timeout` 行为被正确记录；断线后能从最近快照恢复且不丢已提交决策；
  2. **数据**：导出宽表包含 `actor_id/round/origin_unit/choice/latency_ms/confidence/reason`，字段无缺失率 >5% 的列；
  3. **合规**：伦理审查批件到手 **且** 知情同意流程在预实验中走通（**这是硬门禁，不是软任务**）；
  4. 预实验 N≥3 的被试完成全流程且主观负荷反馈可接受。
- **风险与回退**：伦理审查周期不可控（通常 2–6 周日历时间）→ **阶段 3 与阶段 4 并行推进**，先用脚本被试（`Scripted`）压测技术链路；被试量不足 → `weight` 代表性权重 + 报告未加权/加权双结果。
- **人天说明**：8 人天为技术工作量；伦理审查走独立日历时间线。

### 阶段 4｜合成智能体接入（6 人天）

- **交付物**：`src/actors/LLMAgent`（可插拔后端：云 API / 本地模型）；人设构造器（借鉴 Concordia/CAMEL 的 persona 写法）；结构化输出 + 重试 + 失败降级链；LLM 成本与延迟记账模块；`AGENTSOCIETY_LLM_API_KEY` 等密钥管理说明（`.env.example`）。
- **验收标准**：
  1. 合成体按统一协议产出合法消息，Schema 校验通过率 ≥99%（失败自动重试 ≤2 次后降级为 `STAY` 并标记）；
  2. **LLM 服务不可用时闭环不中断**：注入 100% 失败，实验降级为全 `Scripted` 并在日志中标记；
  3. 单轮 50 个合成体的墙钟时间 ≤ 决策窗口 `window_ms`（或证明可异步容忍）；
  4. 成本可核算：每轮 token/费用落盘，能给出"100 轮 × 50 智能体"的成本上界。
- **风险与回退**：Windows 上引入 Ray 依赖（AgentSociety 陷阱）→ **LLM 层不引入 Ray**，用 `asyncio` + 进程池；供应商 API 波动 → 多后端切换 + 降级链。

### 阶段 5｜混合实验（5 人天）

- **交付物**：混合比例控制器（100%真人 → 0%真人的受控替换）；实验编排脚本（一键跑完一个条件矩阵）；H1–H5 假设对应的分析即插即用入口；实验日志与回放包。
- **验收标准**：
  1. 同一场景下，混合比例扫描（如 100/75/50/25/0%）各条件**一键运行**且产出可比对的结果文件；
  2. 每条件可复现：固定 `rng` 种子下两次运行结果逐位一致（合成体侧用确定性 mock 后端验证）；
  3. 宏观偏移量可计算：给出"合成体比例 → 关键单元存量偏移"的定量曲线；
  4. 全部实验数据可回放：给定日志完整重建状态序列。
- **风险与回退**：真人样本量小 → 提高轮次密度与 `weight` 外推，并明确报告外推边界；合成体方差过大 → 固定 persona 分布 + 多次重复取分布而非点估计。

### 阶段 6｜数据分析与出图（5 人天）

- **交付物**：`src/analysis/`（拥挤弹性、揭示偏好 vs 陈述偏好、人机一致性、合成体替代误差）；OD 流向图（flowmap.gl / kepler.gl）；存量演化与误差量化图（对比 SUMO 个体仿真）；可复现分析脚本 + 图表清单。
- **验收标准**：
  1. 每个假设 H1–H5 都有一张图/一张表**且脚本可一键重跑**；
  2. 聚合近似误差有量化结论（与 SUMO 或 Mesa 个体模型对照，给出误差分布而非单点值）；
  3. 所有图表的输入数据、脚本、随机种子三者在仓库内可追溯；
  4. 出图不依赖任何 copyleft 组件（见 `许可证风险.md`）。
- **风险与回退**：统计功效不足 → 预先注册分析计划（pre-registration），把探索性分析明确标注为探索性；SUMO 对照因 EPL-2.0 不便分发 → 只分发**结果数值**与复现命令，不分发 SUMO 二进制。

### 关键路径与并行建议

```
阶段0 ──► 阶段1 ──► 阶段2 ──┬──► 阶段3（含伦理审查，日历时间最长）
                             └──► 阶段4 ──► 阶段5 ──► 阶段6
```
**最早可并行点**：阶段 3 与阶段 4 之间无技术依赖，伦理审查期间即应开发合成体链路。**总净工时 35 人天**；若伦理审查 4 周，单开发者日历工期约 11–12 周。

## 6. 明确"不做什么"

1. **不重写仿真内核去用 CityFlow/AB Street**——它们在本机不可构建，且正是本范式要替代的精细路线。
2. **不把 AgentSociety 当主干**——Windows Ray 陷阱（✅实测）+ 结构上不接纳真人（Lane C 代码级核查）。
3. **不让 Mesa 承担存量-流量语义**——`Cell` 无 `stock`/`flow` 字段（✅实测），聚合量只能从个体反推。
4. **不引入 Julia / Rust / C++ 编译链**——性价比过低，且会同时引入部署与许可证复杂度。
5. **不在主链路引入 Ray**——Windows 上依赖被上游声明排除，属静默缺件风险。

## 7. 局限与未完成事项（如实声明）

1. **Gitee API 需要 token**：`gitee.com/api/v5/search/repositories` 对全部测试查询返回空数组，因此**国内托管平台的高星项目未纳入选型池**。若需补充，须提供 access token 后重新检索。
2. **GitLab / Codeberg / HuggingFace 未逐站检索**：本次仅扫 GitHub，跨平台可能存在更贴合的项目。
3. **`repos.json` 中 37 条许可证为 null**（GitHub API `NOASSERTION`/`NONE`）：本文对这些项目一律标注"须人工核对"，未做任何推断。
4. **标注为 📋元数据的 S/A 档项目本机未实测**（osmnx、geopandas、h3-py、kepler.gl、deck.gl、flowmap.gl、PySD、SurveyJS、movingpandas 等）：其"开箱即用"判断基于**纯 Python/JS 且 PyPI/npm 有发行版**这一元数据事实，存在小概率的 Windows 轮子缺失风险，须在阶段 0 逐条验证。
5. **Mesa 的验证基于本地源码 editable 安装的 4.0.0a0（alpha）**：PyPI 稳定版的 API 差异未在本次验证范围内；用于论文时建议同时记录稳定版行为。
